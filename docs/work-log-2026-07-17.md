## 二、建立 Agent 间二进制传输协议

原有编队 ROS topic 转发使用 MQTT JSON：源 Agent 先把 ROS 消息转换为 Python 字典，再编码为 JSON 发送。对于里程计、TF 等高频消息，这条路径会产生重复字段名、文本编码和对象转换开销。今日增加了 `mqtt_binary` 所需的协议基础，使后续任务能够直接传输 ROS1 serialized bytes，也就是 ROS1 消息对象原生序列化后的字节内容。

首先新增了 binary envelope。Envelope 是通过主 MQTT topic 发送的轻量 JSON 路由信息，它不包含 ROS 字段数据，只携带源 topic、目标 topic、消息类型、frame 策略、ROS MD5、主体大小、有效期和 `transfer_id`。其中 ROS MD5 用于确认源端与目标端使用完全相同的 ROS 消息定义；`transfer_id` 是 64 位传输标识，用于把可能乱序到达的 JSON envelope 和二进制主体正确配对。

协议解析对关键字段进行了严格校验，包括：

- `transfer_id` 必须是 `0..2^64-1` 范围内的整数，不能使用 Python `bool`；
- `payload_size` 必须是非负整数；
- ROS MD5 必须是非空字符串；
- 时间戳和 TTL 必须是有限数值；
- transport、encoding、payload format 和 binary 标记必须与协议固定值一致。

MQTT topic 同时增加了 Agent 间二进制主体路径：

```text
robot/{src_id}/to/{dst_id}/bin
```

目标 Agent 可使用 `robot/+/to/{dst_id}/bin` 形式的单层通配符订阅所有来源。解析器对 Agent 间主 topic、`/bin` 和 `/meta` 使用精确段数匹配，拒绝 `/bin/extra`、`/meta/extra` 等带额外层级的异常 topic，避免误分流。

## 三、实现固定关联头和传输标识

由于 MQTT 不保证不同 topic 之间的到达顺序，二进制主体不能依赖 JSON envelope 先到达。今日为每个二进制主体增加固定 13 字节关联头：

```text
FRB1 + version(1 byte) + transfer_id(8 bytes, big-endian)
```

`FRB1` 用于识别编队二进制协议，version 用于拒绝不兼容格式，`transfer_id` 用于与 envelope 配对。编码和解码集中在 `protocol/binary_payloads.py`，业务层不需要自行拼接或切片字节。实现支持空 ROS body，并拒绝截断数据、错误 magic、未知版本、越界 ID 和非 bytes 主体。

BaseAgent 中增加了线程安全的 `transfer_id` 生成器。每个 Agent 启动时生成一个 32 位随机 session nonce，低 32 位使用递增计数；计数达到上限后重新生成 nonce 并从 1 开始。这样多个 ROS 回调并发发送时仍能获得唯一 ID，也能降低 Agent 重启后与旧缓存传输标识碰撞的概率。

## 四、完善 BaseAgent 配置和发送基础

编队规则规范化现在会明确处理 transport 和 QoS：

- transport 只接受 `mqtt_json` 和 `mqtt_binary`，其他值回落到 `mqtt_json`；
- QoS 只接受 0 和 1，其他值回落到 1；
- 旧规则缺少字段时使用 `mqtt_json + QoS 1`，保持对旧 Agent 的兼容；
- 同一规则内重复的 `(robot_id, dst_topic)` 目标只保留一份。

原有 JSON 编队发送入口增加了 route QoS 参数和布尔返回值。新 binary 发送入口会使用同一目标和 QoS，分别发布 JSON envelope 与带 `FRB1` 关联头的二进制主体，并分别返回 Paho MQTT 客户端是否接受发布请求。

这里的返回值只表示 Paho 是否成功接收请求，不表示 Broker 或目标 Agent 已完成投递。MQTT publish rc 失败也不会自动改发 JSON，因为 QoS 1 消息可能已进入 Paho 的重连队列，立即回退可能造成重复消息。

为限制 Broker 断连时的内存积压，Paho 客户端离线队列上限设置为 1000 条，在途消息上限设置为 20 条。二进制接收、TTL 判断、乱序配对缓存和资源上限尚未在本阶段启用，将在后续 BaseAgent 接收任务中实现。
