## 一、Bridge 数据流修复

### 1.1 `dict_to_ros_msg` 导入错误（关键 bug）

**现象**：Bridge 收到 MQTT 传感器数据后，所有类型化 ROS 发布静默失败。`rostopic list` 显示 `/tf` Publishers: None，`/turtlebot_001/odom` 完全不存在，`/turtlebot_001/map` 被降级为 `std_msgs/String` raw JSON。

**根因**：`bridge/dict_to_ros_msg.py:32` 使用 `from rospy.msg import get_message_class`，但 ROS Noetic 中 `rospy.msg` 模块没有此函数。该函数实际位于 `genpy.message`。

**修复**：`from genpy.message import get_message_class`

**影响范围**：此 bug 导致 Bridge 重构（5月8日）的所有自动类型检测和 TF 路由代码完全失效——数据走到 `_handle_sensor_data` 的 auto-detect 分支后，`dict_to_ros_msg` 抛出 ImportError 被 try/except 静默捕获，回退到 JSON String 发布。修复后链路全通：

```
/tf /tf_static /joint_states          → 标准 ROS 话题
/turtlebot_001/odom /imu /scan /map  → 按机器人路由
```

### 1.2 话题限频参数调优

通过 `rostopic hz` 实测 Turtlebot3 仿真中各话题的实际发布频率：

| 话题 | 实际频率 | 旧限频 | 新限频 | 说明 |
|---|---|---|---|---|
| `/odom` | 25~42 Hz | 10 Hz | **30 Hz** | 旧值丢弃 3/4 数据 |
| `/imu` | 800~1000 Hz | 10 Hz | **50 Hz** | 实际过高，50Hz 够用 |
| `/tf` | ~118 Hz | 10 Hz | **50 Hz** | 太低 RViz 卡顿 |
| `/joint_states` | ~30 Hz | 50 Hz | **30 Hz** | 匹配实际，省带宽 |
| `/scan` | 5 Hz | 5 Hz | 不变 | 刚好匹配 |
| `/map` | 0.8~8.5 Hz | 未订阅 | **新增 2Hz** | gmapping 地图之前完全未转发 |
| `default_freq_limit` | — | 10 Hz | **30 Hz** | 全局默认 |

## 二、命令发送修复

**现象**：Qt 前端选择目标机器人后发送速度命令，Gazebo 中机器人无反应。

**根因**：`qt_frontend/main_window.py:292`，`_on_command` 接收 `(robot_id, action, params)` 三个参数，但调用 `send_cmd` 时丢弃了 `action`，直接将裸 `params`（如 `{"linear": 0.5, "angular": 0.0}`）发送到 MQTT。

Agent 端 `_handle_command` 期望的协议格式是 `{"action": "velocity", "params": {...}}`。因为 `action` 缺失，解析后 `cmd.action = ""`，走到 `Unknown command` 分支，`/cmd_vel` 从未被发布。

**修复**：`send_cmd(robot_id, {"action": action, "params": params})`

## 三、LaserScan 静态 TF 帧补全

**现象**：RViz 添加 LaserScan Display，Fixed Frame 设为 `map`，报错 `Frame [base_scan] does not exist`。

**根因分析**：Turtlebot3 的 `/tf_static`（由 `robot_state_publisher` 发布，包含 `base_footprint → base_link → base_scan` 等静态帧）是 latched topic。Agent 的 `rospy.Subscriber` 订阅 `/tf_static` 无法接收 latched 消息（具体原因未确定，可能是 rospy 实现或时序问题）。

**验证**：容器内 `/tf_static` 有完整数据（`base_link, base_scan, imu_link, caster_back_link`），但 MQTT 上 `robot/turtlebot_001/sensor/tf_static` 完全无数据。手动 `rostopic pub /tf_static` 触发亦无效。

**修复**（workaround）：在 `qt_frontend/launch/station.launch` 中用 `static_transform_publisher` 发布三个关键静态帧：

```xml
base_footprint → base_link       (0, 0, 0.010)
base_link → base_scan            (-0.032, 0, 0.172)
base_link → imu_link             (-0.032, 0, 0.068)
```

`start.sh` 通过 `roslaunch station.launch &` 启动。后续考虑将 bridge 和前端也迁移到 launch 文件中统一管理。
