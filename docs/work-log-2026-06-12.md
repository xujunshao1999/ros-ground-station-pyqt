# 工作日志 — 2026年6月12日

## 一、今日概览

今日主要处理地面站前端中 RViz 原生 `Image` / `Camera` 面板的显示问题。目标是在保留 RViz 原生 `DisplaysPanel` 操作方式的前提下，让用户通过勾选 Display 项目显示图像面板，而不是额外维护一个独立的摄像头 Dock。

本次工作重点不是协议或 MQTT 数据链路，而是 PyQt 主窗口与 RViz C++ 胶水层之间的 Qt widget 承载关系。经过多轮手动测试和方案调整，最终保留中间区域只嵌入 RViz `RenderPanel`，右侧 `Display` 页签上方显示原生 `DisplaysPanel`，下方承载 RViz 原生创建的 `Image` / `Camera` panel。

## 二、问题背景

前端此前为了显示图像数据，在主窗口右侧额外创建了一个“摄像头” `QDockWidget`。这个窗口可以承接 RViz 的 `Image` / `Camera` 面板，但它独立于右侧 `Display` 页签，视觉和操作上与 RViz 原生 Display 管理割裂。

今日希望将图像窗口放到 `Display` 面板下方，并保留 RViz 原生交互方式：用户仍然通过 `DisplaysPanel` 勾选或取消勾选 `Image` 项来控制图像显示。

排查过程中确认了几个关键约束：

- 中间区域必须继续只嵌入 `rviz::RenderPanel`，不能改为完整 `rviz::VisualizationFrame`，否则主视图会变成整套 RViz 窗口。
- `Image` / `Camera` 这类 RViz Display 会创建 `rviz::PanelDockWidget`，默认挂在隐藏的 `VisualizationFrame` 下，因此仅勾选 Display 项时不会自动出现在 PyQt 主界面中。
- 直接在 `configChanged()` 信号处理过程中重挂 `PanelDockWidget`，会与 RViz 自身创建或销毁 Display 的生命周期冲突，勾选和取消勾选时可能触发不稳定崩溃。

## 三、方案调整

今日尝试过多个承载方案，并根据手动测试结果逐步收敛。

最初尝试将 Image 窗口直接放入 `Display` 页签的普通垂直布局。该方案可以让窗口出现在 `Display` 下方，但会破坏 RViz 原生 `PanelDockWidget` 的停靠语义，出现弹出按钮失效、Display 面板被挤压等问题。

随后尝试用嵌入式 `QMainWindow` 作为 dock host，让 RViz 的 `PanelDockWidget` 继续走 Qt 原生 dock 机制。手动测试发现 dock 布局仍会将 Image 面板压到右下角或只占下方区域的一部分，布局不稳定。

之后短暂尝试将完整 `rviz::VisualizationFrame` 嵌入中间区域，以给 RViz 原生 panel 提供宿主。该方案不符合地面站三栏布局设计，会把中间 Render 区域变成完整 RViz 窗口，已及时撤回，并补充测试防止再次误改。

最终采用的方案是：

- 中间区域继续嵌入 `rviz::RenderPanel`。
- 右侧 `Display` 页签内部使用垂直 `QSplitter`。
- 上方子区域放 RViz 原生 `DisplaysPanel`。
- 下方子区域默认隐藏，作为 RViz `Image` / `Camera` panel 的宿主。
- C++ 胶水层监听 `DisplaysPanel` 的配置变化，延迟到当前 Qt 事件结束后，再把 RViz 创建的 `PanelDockWidget` 移入下方宿主区域。

这个方案保留了用户“勾选 Display 项目触发显示”的操作方式，也避免把完整 RViz 窗口嵌入中间 Render 区域。

## 四、实现细节

`qt_frontend/main_window.py` 中，`Display` 页签从单个容器改为垂直 `QSplitter`：

- `_display_panel_holder` 承载 RViz 原生 `DisplaysPanel`。
- `_image_panel_container` 承载 RViz 创建的 `Image` / `Camera` panel。
- `_image_panel_container` 初始隐藏，设置最小高度 160、最大高度 280，避免一开始挤压 Display 树。
- `_image_panel_layout` 通过 `set_dock_layout()` 传给 C++ native 层。

`qt_frontend/native/rviz_widget.cpp` 中保留 `RenderPanel` 作为 `create_rviz_widget()` 的返回 widget，并对 Image panel 重挂做了延迟处理：

- `DockExtractor::onConfigChanged()` 只标记配置变更，并通过 `QTimer::singleShot(0, ...)` 排队执行 `moveImagePanels()`。
- `dock_move_pending` 避免同一轮配置变更重复排队。
- `move_image_panels_to_layout()` 查找 `rviz::PanelDockWidget`，只处理标题为 `Image` 或 `Camera` 的窗口。
- 重挂前设置 `QSizePolicy::Expanding`，并对 `QVBoxLayout` 设置 stretch，让 Image panel 填满下方区域。
- 不使用 `setWidget(nullptr)` 拆内容 widget，也不使用额外的主窗口级 Dock。
