# 工作日志 — 2026年6月10日

## 一、今日概览

今日主要围绕地面站前端嵌入式 RViz 的配置管理能力进行完善。此前 RViz 右侧 Display 面板中的默认条目由 C++ 胶水层固定创建，启动时只包含 `Grid` 和 `TF`，虽然仓库中存在 `qt_frontend/config/default.rviz`，但实际没有按 `.rviz` 文件恢复 Display 配置。今日将这一部分改为可通过 `.rviz` 文件加载和保存，并补齐关闭窗口前的未保存变更提示。

今日完成提交：

- `cb341fb feat: 支持RViz配置加载保存`
- `42b767e feat: 关闭前提示保存RViz配置`

整体目标是让前端 RViz 的 Display 配置从“代码固定创建”推进到“配置文件驱动、用户可调整、可保存恢复”的闭环，同时避免之前开发中出现过的“加载 `.rviz` 后鼠标无法操作 RViz 视图”的问题。

## 二、RViz Display 配置来源排查

今日首先检查了当前地面站前端 RViz Display 条目的来源。结论是：启动时默认 Display 并不是从 `.rviz` 文件读取，而是在 `qt_frontend/native/rviz_widget.cpp` 中手动创建。

关键代码路径包括：

- `qt_frontend/main.py` 使用 `qt_frontend.main_window.MainWindow` 作为当前前端入口。
- `qt_frontend/main_window.py` 的 `_init_rviz()` 只调用 `create_rviz_widget()` 创建嵌入式 RViz，并没有调用 `load_config()`。
- `qt_frontend/native/rviz_widget.cpp` 中 `create_rviz_widget()` 在初始化 `VisualizationManager` 后调用 `removeAllDisplays()`，再手动创建 `rviz/Grid` 和 `rviz/TF`。
- C++ 层虽然导出了 `load_config()`，但此前函数体实际忽略 `config_path`，直接返回成功。

这说明 `qt_frontend/config/default.rviz` 虽然存在，但在当前主线前端中没有真正参与 Display 初始化。用户手动在 Display 面板中添加的 LaserScan、Map 等 Display 也不会在下次启动时自动恢复。

## 三、`.rviz` 加载方案与鼠标交互问题处理

此前开发中曾尝试使用 RViz 原生的整帧加载能力，但出现过 RViz 鼠标交互失效的问题。今日没有继续使用 `VisualizationFrame::loadDisplayConfig()`，而是实现了一个受限的 `.rviz` 加载策略。

具体做法是：

- 使用 `rviz::YamlConfigReader` 读取 `.rviz` YAML 文件。
- 只读取根节点中的 `Visualization Manager`。
- 调用 `VisualizationManager::load()` 加载 Displays、Global Options 和 Views。
- 不加载 RViz 原生主窗口的 Panels、工具栏、dock 布局和其他窗口级状态。
- 加载完成后显式恢复 `rviz/MoveCamera` 工具，并重新设置 `RenderPanel` 的 focus 和 mouse tracking。

这样做的原因是，当前前端只把 RViz 的 `RenderPanel` 和 `DisplaysPanel` 嵌入 PyQt 主窗口，并没有完整使用 RViz 原生 `VisualizationFrame` 的主窗口布局。如果直接加载完整 `.rviz`，RViz 会尝试恢复原生窗口、Panel、View 和 Tool 状态，这些状态在嵌入式场景下容易破坏鼠标交互。

今日在 `qt_frontend/native/rviz_widget.cpp` 中新增了 `restore_interaction_state()`，用于在创建 RViz 和加载配置后统一恢复相机交互状态。该函数会查找或创建 `rviz/MoveCamera`，将其设置为默认工具和当前工具，并重新设置 `RenderPanel` 的焦点策略。

## 四、启动时加载 `default.rviz`

在前端启动流程中，今日将 `qt_frontend/main_window.py` 的 `_init_rviz()` 改为创建 RViz 后自动加载：

```text
qt_frontend/config/default.rviz
```

如果加载成功，右侧 Display 面板中的条目来自该 `.rviz` 文件。如果加载失败，例如文件缺失、YAML 解析失败或缺少 `Visualization Manager` 节点，则前端会保留 C++ 层内置的基础默认状态，并将 fixed frame 回退为 `map`。

该策略保证了两点：

- 正常情况下，用户可以通过 `.rviz` 灵活定义默认 Display，例如 `Grid`、`TF`、`LaserScan`、`Map`、`PointCloud2`、`Image` 等。
- 配置文件异常时，前端不会因为 `.rviz` 问题直接无法启动或出现空白 RViz。

## 五、加载与保存按钮

今日在地面站前端补充了 RViz 配置的手动加载和保存入口。入口位置选择在顶部“视图”菜单和主工具栏：

- 菜单：`视图 -> 加载 RViz 配置...`
- 菜单：`视图 -> 保存 RViz 配置...`
- 工具栏：`加载 RViz`
- 工具栏：`保存 RViz`

这样放置的原因是 `.rviz` 配置属于全局视图配置，影响的是整个 RViz Display、Global Options 和 View 状态，而不是某一个具体 Display 条目。将入口放在顶部菜单和工具栏，比嵌入右侧 Display 树更符合用户对“视图配置”的预期，也避免干扰 RViz 原生 Display 面板。

保存功能在 C++ 层新增了 `save_config()`。保存时同样采用受限策略：只写入 `Visualization Manager`，不写入 RViz 原生窗口布局和 Panels。这样保存出的 `.rviz` 文件可以被当前嵌入式前端稳定加载，也避免把不适合 PyQt 嵌入环境的 RViz 原生窗口状态写入配置。

手动测试中，加载和保存功能可以正常工作，用户也确认了基本行为没有问题。

## 六、关闭窗口前的未保存变更提示

在加载和保存功能完成后，继续补充了关闭窗口前的未保存变更提示。目标是：当用户在 RViz Display 面板中添加、删除或修改 Display 后，如果没有保存配置，点击关闭窗口时应提示是否保存。

最初实现时使用 RViz 的 `PropertyTreeModel::configChanged()` 信号维护 `config_dirty` 标记。实际手动测试发现，点击地面站窗口关闭按钮时前端仍会直接退出，说明仅依赖当前连接的 `configChanged()` 信号不够可靠，某些 Display 改动路径没有稳定触发 dirty 标记。

随后将检测策略调整为“双保险”：

- 保留 `config_dirty` 信号标记，作为快速路径。
- 在加载和保存成功后，序列化当前 RViz Display 配置，保存为一份快照。
- 关闭窗口时，实时序列化当前 Display 和 Global Options 配置，并与上一次快照比较。
- 如果 dirty 标记为真，或当前快照与基线快照不同，就认为 RViz Display 配置发生了变化。

这样即使 RViz 没有发出 `configChanged()` 信号，只要最终 Display 配置确实不同，关闭前也能检测出来。

关闭提示的交互逻辑如下：

- `Save`：保存 RViz 配置后关闭窗口。
- `Discard`：不保存，直接关闭窗口。
- `Cancel`：取消关闭，回到前端。

用户手动测试后确认该提示可以触发。

## 七、当前配置文件路径与直接覆盖保存

关闭提示实现后，又进一步优化了保存交互。用户反馈希望提示中说明当前加载的 `.rviz` 配置文件是哪一个，并且选择保存时直接覆盖该文件，而不是每次都弹出保存路径选择框。

今日将前端增加了当前 RViz 配置路径状态：

- 启动时加载 `qt_frontend/config/default.rviz` 成功后，记录为当前配置路径。
- 用户通过“加载 RViz 配置...”加载其他 `.rviz` 文件成功后，更新当前配置路径。
- 用户通过“保存 RViz 配置...”主动保存到某个文件成功后，也更新当前配置路径。

关闭窗口发现配置变化时，提示框会显示当前路径，例如：

```text
当前 RViz 配置文件：/path/to/default.rviz
```

如果用户选择 `Save`，前端会直接调用 `_save_rviz_config(current_path)` 覆盖当前文件。只有在没有当前路径的异常情况下，才回退到保存文件对话框。

用户手动测试后确认该交互没有问题。
