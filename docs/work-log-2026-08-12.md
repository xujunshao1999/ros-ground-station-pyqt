## 二、梳理录制链路与安全边界

录制功能开始实现前，先把运行链路和几个容易混淆的概念固定下来。

本次录制对象是地面站本机 `ROS_MASTER_URI` 指向的 roscore 中可见的话题。普通机器人话题经 Bridge 发布后使用 `/{robot_id}/{source_topic}` 形式，例如机器人 `/scan` 会在地面站侧成为 `/turtlebot_001/scan`。`/tf` 和 `/tf_static` 是例外，它们由多个机器人共享标准公共话题名称，通过 frame 命名空间区分机器人，因此不能再添加机器人 ID 前缀。

录制基础路径由保存目录和录制名称组合而成，但不带 `.bag` 扩展名，例如 `/data/records/patrol_01`。该路径作为 `rosbag record -O` 的参数，实际运行时可能产生：

- `patrol_01.bag`；
- 正在写入的 `patrol_01.bag.active`；
- 分包模式下的 `patrol_01_*.bag` 和 `patrol_01_*.bag.active`。

停止录制时必须向 `QProcess.processId()` 对应的进程发送 `SIGINT`。这是为了让 `rosbag` 正常写完索引并关闭 `.active` 文件。Qt 的 `terminate()` 发送 `SIGTERM`，不能替代正常停止流程。用户主动强制终止仍然保留，但会作为失败结果处理，避免把可能未完成索引的文件显示成已正常保存。

## 三、建立录制配置、校验和命令构造

任务 1 先建立了不依赖 ROS 运行环境的纯配置层。新增的 `RecordingConfig` 集中保存录制名称、输出目录、话题列表、压缩方式、分包方式和缓冲区大小，并通过 `output_base` 统一生成录制基础路径。

录制名称现在要求非空，可以使用 Unicode 字母、数字、中文、连字符和下划线，但禁止路径分隔符以及 `.`、`..` 等特殊路径名称。输出目录必须是绝对路径；目录已经存在时必须可写，不存在时其父目录必须存在且可写。话题会按用户传入顺序去重，并要求全部以 `/` 开头。

参数构造覆盖以下行为：

- 默认使用 LZ4 压缩，也可以选择 BZ2 或不压缩；
- buffer 使用 `--buffsize=<MiB>` 格式；
- 按大小分包使用 `--split --size=<MiB>`；
- 按时长分包使用 `--split --duration=<数值><s|m|h>`；
- 分包时自动增加 `--repeat-latched`，保证 latched 话题在新分包中重复写入；
- 不加入会自动删除旧分包的 `--max-splits`。

同名输出冲突检查只在录制基础路径的父目录中进行非递归匹配，避免跨目录误判，也避免新录制覆盖已有 `.bag` 或 `.bag.active` 文件。

## 四、构建推荐话题分组与刷新选择规则

任务 2 解决“哪些话题应该默认推荐录制”的问题。推荐话题必须同时满足三个条件：话题出现在 `transmit_config.yaml` 的订阅配置中、对应机器人当前在线、映射后的话题已经出现在地面站本地 ROS Master 中。配置存在但本地话题尚未发布时不会显示为可录制推荐项；离线机器人的配置也不会进入推荐组。

话题模型分成三类：

- 公共变换：`/tf` 和 `/tf_static`；
- 按机器人 ID 分组的推荐话题；
- 其他本地 ROS 话题。

`rostopic list -v` 的文本解析同时处理发布者和订阅者区域，按完整 topic 去重，重复记录中优先保留非空消息类型。隐藏话题的判断按路径 segment 进行，只要任意非空 segment 以下划线开头，就标记为隐藏，但仍保留在模型中供界面按需显示。

刷新选择逻辑在实现时发现了计划接口歧义：只有“旧选择”和“新分组”无法区分新出现的推荐话题与用户主动取消的旧推荐话题。最终将接口扩展为可选的 `previous_groups` 参数。首次加载传入 `previous=None`，默认选择全部推荐话题；刷新时同时传入旧分组，只自动勾选相较旧分组真正新增的推荐话题，不会把用户主动取消的旧推荐项重新选中。消失的话题会从选择中移除，新出现的普通本地话题不会自动选中。

## 五、实现录制进程状态机

任务 3 新增 `RosbagRecorder`，使用 PyQt 的 `QProcess` 管理 `rosbag record`。状态机包含空闲、启动中、录制中、保存中、已完成和失败六个状态。完成与失败都会保留结果状态，只有显式调用 `reset()` 才回到空闲，防止结果页被自动清空。

启动时会继承 `QProcessEnvironment.systemEnvironment()`，保留启动脚本 source ROS 后得到的 `PATH`、`PYTHONPATH` 和 ROS package 环境。如果主窗口传入 `ros_master_uri`，只覆盖 `ROS_MASTER_URI`，确保录制进程与地面站 ROS 检测使用同一个 Master。

状态机目前支持：

- 启动前校验配置并创建允许创建的输出目录；
- 使用结构化的 program 和 arguments 启动进程，不拼接 shell 命令；
- 在启动中或录制中向有效 PID 发送 `SIGINT`；
- 保存阶段拒绝重复停止和重复启动；
- 活动状态下按 1 秒间隔上报录制时长和文件大小；
- 只统计当前录制名称对应的输出文件；
- 使用 20 行 stderr 环形缓冲生成失败摘要；
- 正确合并被 `QProcess` 分块读取的 stderr 半行；
- 处理 Qt 先发 `errorOccurred(Crashed)`、后发 `finished` 的真实信号顺序，在最终错误中保留退出码和 stderr；
- 强制终止后按失败处理。

这些测试全部使用注入的假 `QProcess`，没有在单元测试中启动 ROS 或真实 `rosbag`。

## 六、完成左侧录制配置面板

任务 4 新增了 `RecordingPanel`。面板面向地面站左侧约 360 px 的窄栏，采用单列滚动布局，没有使用多列表格。主要控件包括 ROS 状态、刷新按钮、录制名称、话题搜索树、隐藏话题开关、保存目录、压缩与分包参数、文件预览、选择摘要、校验错误和开始按钮。

话题树按“推荐话题”和“其他本地 ROS 话题”分区，推荐区继续分成“公共变换”和机器人子组。顶层分类支持批量勾选和取消，叶节点保存完整 topic 和消息类型，并通过 tooltip 展示长文本。搜索只改变可见性，不改变已经勾选的内容。

隐藏话题默认不显示，也不会在首次加载时静默保持选中。用户打开“显示隐藏话题”后可以主动选择；再次关闭时，面板会取消所有已选隐藏话题，并在摘要中显示取消数量，避免看不见的话题继续参与录制。

参数区实现了真正的折叠显示。分包模式切换时按大小和按时长控件整行切换，不会留下空标签。BZ2 模式会显示 CPU 占用提示。名称或目录变化会实时更新 `<output_dir>/<name>.bag` 文件预览，任何字段变化都会重新校验配置。只有本地 ROS 可用、至少选择一个话题且配置无错误时，“开始录制”按钮才会启用。

面板使用 `QSettings("ros-ground-station", "qt-frontend")` 保存输出目录、压缩、分包、buffer 和隐藏话题偏好，录制名称不持久化，每次构造时按当前时间生成。恢复历史偏好时，如果旧配置中出现已经不支持的枚举值，会回退到 LZ4 和不分包默认值，不会阻止面板启动。

本机实际环境为 Qt 5.12.8 / PyQt 5.14.1，缺少部分较新版本的 `QFormLayout.setRowVisible()`。实现改为使用 `labelForField()` 同时控制标签和字段可见性，因此兼容当前环境，也满足计划中的窄栏联动要求。
