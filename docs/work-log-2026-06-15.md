# 工作日志 — 2026年6月15日

## 一、今日概览

今日主要修复地面站前端 RViz `Image` 面板的浮动与拖拽问题。此前在右侧 `Display` 页签中勾选 `Image` 后，下方可以出现 RViz 原生 Image Panel，但点击 Image Panel 自身的浮动按钮后，窗口仍被限制在下方区域，无法像 Qt Dock 一样拖出或自由移动。

本次工作延续 6 月 12 日的 Image Panel 承载方案，在保留“勾选 Display 后先出现在下方区域”的体验基础上，将下方宿主从普通 `QVBoxLayout` 调整为嵌入式 `QMainWindow` dock host，让 RViz 创建的 `rviz::PanelDockWidget` 继续使用 Qt 原生 dock 机制。

## 二、问题排查与原因

排查确认问题不在 MQTT、ROS topic 或图像数据链路，而在 PyQt 主窗口与 RViz C++ 胶水层之间的 widget 承载方式。

旧实现中，`qt_frontend/main_window.py` 创建 `_image_panel_container` 和 `_image_panel_layout`，并通过 `set_dock_layout()` 将普通 `QVBoxLayout` 指针传给 native 层。`qt_frontend/native/rviz_widget.cpp` 在检测到 RViz Display 配置变化后，会查找标题为 `Image` 或 `Camera` 的 `rviz::PanelDockWidget`，再把它直接 `addWidget()` 到该普通布局中。

这种方式能让 Image Panel 显示在 `Display` 页签下方，但也破坏了 `PanelDockWidget` 原本依赖 `QMainWindow` 的停靠语义。结果是面板看起来像 Dock，但实际已经被普通布局约束，点击浮动按钮后仍无法脱离下方区域。

## 三、修复方案

本次采用的修复方案是保留现有右侧 `Display` 页签结构，但将下方 Image 宿主替换为嵌入式 `QMainWindow`：

- `Display` 页签仍使用垂直 `QSplitter`。
- 上方区域继续承载 RViz 原生 `DisplaysPanel`。
- 下方区域继续默认隐藏，用于承载 RViz `Image` / `Camera` panel。
- 下方区域内部新增 `_image_dock_host = QMainWindow()`，开启 `AllowNestedDocks` 和 `AllowTabbedDocks`。
- Python 层通过新的 `set_dock_host()` 将 `QMainWindow` 指针传给 native 层。
- native 层收到 RViz 创建的 `PanelDockWidget` 后，使用 `addDockWidget(Qt::BottomDockWidgetArea, dw)` 挂入 dock host，而不是再放入普通 `QVBoxLayout`。

同时，native 层显式保留 `DockWidgetFloatable` 和 `DockWidgetMovable` 特性，并设置 `Qt::AllDockWidgetAreas`，让 Image Panel 能正常浮动和拖拽。

## 四、实现细节

`qt_frontend/main_window.py` 中新增 `_image_dock_host`，并在 RViz 初始化后调用 `lib.set_dock_host()`。原来的 `set_dock_layout()` ctypes 声明保留，以维持 native 接口兼容，但主窗口路径已改用 dock host。

`qt_frontend/native/rviz_widget.cpp` 中，`RvizInstance` 的宿主字段从 `QVBoxLayout* dock_layout` 改为 `QMainWindow* dock_host`。`move_image_panels_to_layout()` 仍负责延迟处理 RViz 创建的 `Image` / `Camera` panel，但重挂方式改为 `QMainWindow::addDockWidget()`。

`qt_frontend/panels_setup.py` 也同步补齐了 `set_dock_host()` 包装和 Display 页签下方 dock host，避免 C++ 主程序嵌入 Python 面板的备用入口与主窗口入口行为不一致。该文件中原本未使用的一批导入也一并清理，保证 lint 检查干净。
