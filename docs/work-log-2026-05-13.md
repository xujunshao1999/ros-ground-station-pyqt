## 一、UI/UX 设计方向确认

### 1.1 使用 `ui-ux-pro-max` 生成设计建议

本次优化前先使用 `ui-ux-pro-max` 技能查询适合本项目的设计系统。输入关键词为：

```text
robotics ground station operations dashboard professional realtime monitoring
```

得到的方向是“实时监控 / 运维控制台”类型界面，建议采用深色高对比主题、清晰状态色、稳定 hover 状态、明确焦点状态和高可读性文本。结合本项目实际，最终没有采用过度 OLED 黑或强霓虹风格，而是收敛到更适合长期观察的中性深灰蓝配色。

### 1.2 目标界面风格

本项目是机器人地面站，不是营销页或展示型页面，因此界面优化目标是：

- 保持信息密度，不做大面积装饰。
- 让 RViz 保持视觉中心，左右面板作为操作和配置辅助。
- 颜色层级自然，避免纯黑、亮灰、强红之间跳变。
- 急停按钮必须醒目，但不能让整个界面被高饱和红色打断。
- 表格、树、输入框、状态栏使用统一的控制台组件风格。

## 三、配色迭代记录

本日界面配色经历了三版迭代。

### 3.1 第一版：深色实时监控台

第一版采用接近 OLED 的深色主题，背景接近 `#020617`，主色使用亮青蓝，急停按钮使用高饱和红。

**问题**：

- 外层背景接近纯黑，RViz 中央区域是中灰，左右面板接近纯黑，视觉断层明显。
- 右侧 Display 面板和左侧控制面板过暗，中央 RViz 显得像单独嵌入的灰色区域。
- 急停按钮红色过亮，抢占了过多注意力。

### 3.2 第二版：深 slate 层级

第二版将背景提高到深 slate，并降低急停红饱和度：

- 背景改为 `#111827`
- 面板改为 `#172033` / `#202a3d`
- 主高亮蓝改为 `#60a5fa`
- 急停红改为 `#dc3f45`

**效果**：整体比第一版自然，但从截图看仍存在蓝黑面板、灰色 RViz、大输入框之间割裂的问题。

### 3.3 第三版：中性深灰蓝

第三版进一步去除过强蓝黑感，增加独立输入色：

- 背景：`#161a22`
- 面板：`#1c2330`
- 次级面板：`#232c3b`
- 输入框：`#202838`
- 边框：`#394355`
- 主色：`#7aa7d9`

**最终效果**：

- 左右面板与 RViz 中央灰背景之间过渡更自然。
- 右侧发送页大文本框不再像一块突兀的浅色插入面板。
- 顶部和底部状态标签有统一轻量背景，不再像零散黑色块。
- 急停按钮保持清晰可见，但不会破坏整体配色。

## 四、按钮与状态样式优化

### 4.1 急停按钮统一

原来急停按钮在 `main_window.py` 和 `command_panel.py` 中分别写了局部 stylesheet，例如：

```python
QPushButton{background:#d00;color:white;...}
```

本次改为统一设置对象名：

```python
btn.setObjectName("dangerButton")
```

然后在 `theme.py` 中统一维护：

```css
QPushButton#dangerButton {
    background-color: #dc3f45;
    color: white;
    border-color: #dc3f45;
    font-weight: 700;
}
```

这样主工具栏“全部急停”和命令面板“急停”保持一致，也便于后续继续微调危险操作风格。

### 4.2 MQTT / ROS 状态颜色统一

主窗口中 MQTT 连接状态和 ROS Master 状态不再硬编码 `green` / `red`，改用主题常量：

```python
from qt_frontend.theme import DANGER, SUCCESS
```

使用统一状态色可以避免不同面板各自使用默认绿色/红色造成视觉不一致。

## 五、输入错误状态优化

`DataSenderPanel` 原先在 JSON 解析失败时直接覆盖 QTextEdit 的 stylesheet：

```python
self._json_edit.setStyleSheet("QTextEdit { border: 2px solid red; }")
```

这会绕过全局主题，且恢复时需要清空局部样式。本次改为 Qt 动态属性：

```python
self._json_edit.setProperty("invalid", True)
self._json_edit.style().unpolish(self._json_edit)
self._json_edit.style().polish(self._json_edit)
```

主题中统一定义：

```css
QTextEdit[invalid="true"] {
    border: 2px solid #dc3f45;
}
```

这样错误状态和整体主题保持一致，后续其他输入组件也可以复用同样模式。

## 六、三栏布局优化与问题修复

### 6.1 初始目标：左右中比例调整

用户希望左右中接近 `1:2:1`。最初将 splitter 设置为：

```python
self._splitter.setSizes([400, 800, 400])
```

但实际启动后中间 RViz 仍偏窄，说明问题不只是比例数值。

### 6.2 实际更合适的布局

经过截图确认，右侧 RViz Display 面板不需要和左侧控制面板等宽。更合理的布局是：

- 左侧控制面板保持足够宽度，避免滑块、按钮和机器人详情被压缩。
- 右侧 Display / 摘要 / 发送 / 流量面板保持可用但不过宽。
- 中间 RViz 优先获得剩余空间。

最终配置：

```python
left.setMinimumWidth(320)
right.setMinimumWidth(280)
self._splitter_sizes = [360, 920, 320]
```

### 6.3 根因：RViz 异步插入导致 splitter 比例失效

布局比例最初看起来“不生效”的原因在 `_init_rviz()`。

原代码逻辑：

```python
old = self._splitter.widget(1)
if old:
    old.hide()
    old.deleteLater()
self._splitter.insertWidget(1, rviz_widget)
```

问题是 `insertWidget(1, rviz_widget)` 是插入，不是替换。旧的“加载中...”占位控件只是 `deleteLater()`，在事件循环真正删除前 splitter 会短暂变成多列，并重新分配尺寸。因此启动后用户看到的布局和 `setSizes()` 预期不一致。

修复后：

```python
old = self._splitter.replaceWidget(1, rviz_widget)
if old:
    old.deleteLater()
self._splitter.setStretchFactor(1, 1)
self._apply_splitter_layout()
```

同时新增：

```python
def _apply_splitter_layout(self) -> None:
    self._splitter.setSizes(self._splitter_sizes)
```

并在初始化阶段和 RViz 替换后都调用，保证异步加载完成后比例仍然生效。
