## Docker 文件修改

### `docker/Dockerfile.ros`

新增 apt 包：

| 包名 | 用途 |
|---|---|
| `ros-noetic-turtlebot3-gazebo` | Gazebo 仿真环境 |
| `ros-noetic-turtlebot3-slam` | SLAM 建图（gmapping/karto/cartographer） |
| `ros-noetic-slam-gmapping` | gmapping 节点 |
| `ros-noetic-gazebo-plugins` | 差分驱动/激光/IMU 等 Gazebo 插件 |
| `ros-noetic-rviz` | 3D 可视化 |

### `docker/supervisord-turtlebot3.conf`（新建）

4 个程序：

- `roscore` — 容器内 ROS Master
- `agent` — ROS ↔ MQTT 桥接，`ROBOT_ID` 和 `BROKER_HOST` 从环境变量注入
- `turtlebot3` — `turtlebot3_world.launch`（含障碍物世界），启动前等待 roscore 就绪，软件渲染适配 Intel GPU
- `slam` — `turtlebot3_slam.launch slam_methods:=gmapping`（内置 bringup + gmapping + RViz），等待 roscore 就绪

### `docker-compose.yml`

新增 `robot-turtlebot-001` 服务：

- `ROBOT_ID=turtlebot_001`，`TURTLEBOT3_MODEL=burger`
- 挂载 `/tmp/.X11-unix` + `/dev/dri` → Gazebo / RViz 窗口显示
- 挂载独立的 `supervisord-turtlebot3.conf` 覆盖默认配置

### `agent/config.yaml`

- `robot_id` 改为 `turtlebot_001`（容器环境变量覆盖优先）
- `subscriptions` 预置 `/odom`、`/scan`、`/imu`、`/tf` 四个话题

## 调试记录

| 问题 | 根因 | 解决 |
|---|---|---|
| `ros:noetic-robot` 拉取失败 | ROS Noetic EOL，官方镜像移除 | `docker compose build --pull=false` 用本地缓存 |
| Gazebo 启动后 crash（segfault） | Intel Mesa iris 驱动 CCS 3D 纹理 bug | `LIBGL_ALWAYS_SOFTWARE=1` 强制软件渲染 |
| `robot_description` KeyError | turtlebot3 launch 和 roscore 同时启动，spawn_model 读参数时 roscore 未就绪 | `until rostopic list; do sleep 1; done` 等待 |
| 世界有障碍物但无机器人模型 | `turtlebot3_empty_world` 无杂物，改用 `turtlebot3_world` 后依然缺插件 | 改用全功能 launch |
| RViz 不显示 | `turtlebot3_gmapping.launch` 只启 gmapping 节点，缺少 bringup（无 odom/joint_states） | 改为 `turtlebot3_slam.launch slam_methods:=gmapping`（内置 bringup + rviz） |
| `/odom` `/joint_states` 无发布者 | 缺少 `ros-noetic-gazebo-plugins`（差分驱动/激光/IMU 插件），且 apt 缓存过期 | `apt-get update` 后安装 `ros-noetic-gazebo-plugins` |
| Gazebo FPS 低 | 软件渲染性能限制 | 已知问题，待后续优化（MESA 环境变量或硬件加速） |

## 启动方式

```bash
# 1. 允许 Docker 访问 X11
xhost +local:docker

# 2. 启动容器
docker compose up -d robot-turtlebot-001

# 3. 查看日志
docker compose logs -f robot-turtlebot-001

# 4. Gazebo + RViz 窗口自动弹出
```
