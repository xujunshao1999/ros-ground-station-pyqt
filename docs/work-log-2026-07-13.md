## 二、补齐机器人端 Agent 启停脚本

今天先处理机器人端 Agent 的真实运行入口。此前停止脚本使用 `pkill -f "agent.main"` 这类宽匹配方式，开发环境里能快速清理进程，但真实部署时风险较高：如果同一台机器上还有其他 Python 命令或相似进程，可能出现误杀；如果进程名或启动方式变化，也可能找不到目标。

新的机器人端启动脚本放在：

```text
agent/scripts/start.sh
```

脚本会自动计算项目根目录，默认读取：

```text
agent/configs/default.yaml
```

也可以通过 `CONFIG_PATH` 指定某台机器人的独立配置，例如：

```bash
CONFIG_PATH=agent/configs/husky_001.yaml ./agent/scripts/start.sh
```

启动脚本还会写入：

```text
logs/agent.pid
logs/agent.log
```

对应停止脚本放在：

```text
agent/scripts/stop.sh
```

停止脚本不再全局 `pkill`，而是读取 PID 文件，并在停止前检查 `/proc/<pid>/cmdline` 是否确实包含 `agent.main`。如果 PID 文件指向无关进程，脚本只删除过期 PID 文件，不会杀掉该进程。这是为了防止 PID 被系统复用后误杀其它服务。

这里也明确了默认使用方式：真实部署下一台机器人上位机通常只跑一个 Agent，所以停止时不需要手动输入 `PID_FILE=logs/agent.pid`，直接执行即可：

```bash
./agent/scripts/stop.sh
```

只有一台机器同时跑多个 Agent 时，才需要给每个 Agent 单独指定不同的 `PID_FILE` 和 `LOG_FILE`。

## 三、完善地面站前端启停脚本

随后检查并完善了 `qt_frontend/scripts/start.sh` 和 `qt_frontend/scripts/stop.sh`。真实部署边界是：地面站脚本只管理地面站本地进程，不管理机器人端 Agent。机器人 Agent 跑在各自机器人上位机上，由机器人侧脚本独立启动和停止。

地面站启动脚本现在会在检查 `rostopic` 之前先 source ROS 环境：

```bash
ROS_SETUP="${ROS_SETUP:-/opt/ros/noetic/setup.bash}"
source "$ROS_SETUP"
```

这样新终端不需要用户提前手动 source ROS。非标准 ROS 安装路径也可以通过 `ROS_SETUP` 覆盖。

脚本还新增了地面站本地进程 PID 记录：

```text
logs/pids/qt_frontend.pid
logs/pids/bridge.pid
logs/pids/station.launch.pid
```

`stop.sh` 会优先按这些 PID 文件停止 Qt 前端、MQTT-ROS Bridge 和 station launch，并在停止前检查命令行是否符合预期。PID 不存在、PID 文件为空或 PID 指向无关进程时，脚本会清理 PID 文件并跳过杀进程。为了兼容旧版启动脚本没有 PID 文件的情况，默认 PID 目录下仍保留了 `pkill` 兜底逻辑，但只作为过渡清理方式。

这次也把 `stop.sh` 中旧的 Agent 停止提示移除，避免让地面站使用者误以为地面站停止流程会直接管理机器人端进程。

## 四、调整 Agent 默认配置路径

今天还把机器人端默认配置从：

```text
agent/config.yaml
```

迁移为：

```text
agent/configs/default.yaml
```

这样目录语义更符合真实部署：`agent/configs/` 下可以放多份机器人配置，例如：

```text
agent/configs/turtlebot_001.yaml
agent/configs/husky_001.yaml
```

一台机器人上位机只运行一个 Agent 时，可以直接维护 `agent/configs/default.yaml`；多机器人或仿真环境则使用 `agent/configs/<robot_id>.yaml`。同步修改了 `agent/scripts/start.sh` 和 `agent/main.py` 的默认配置路径，README 中的配置说明也更新为新的目录结构。

这次迁移避免了 `agent/config.yaml` 给人“仓库只有一个机器人配置”的误导，也减少后续真实部署时多机器人配置互相覆盖的风险。

- 启动与停止顺序：地面站和机器人端分别启动、分别停止；
- 验证命令：MQTT、ROS topic、Bridge 重发布和 HTTP stream 检查；

## 六、增加 RViz native 构建脚本

部署文档初版中仍然要求手动执行：

```bash
cd qt_frontend/native
mkdir -p build
cd build
cmake ..
make -j$(nproc)
```

这类命令在现场部署时容易因为工作目录不对、ROS 环境未 source 或并行参数写错而失败。今天新增了：

```text
qt_frontend/scripts/build_rviz_widget.sh
```

脚本会自动定位项目根目录，默认 source `/opt/ros/noetic/setup.bash`，也支持通过 `ROS_SETUP` 覆盖 ROS 安装路径。随后自动创建 `qt_frontend/native/build`，执行 `cmake ..` 和 `make -j"$JOBS"`，构建完成后检查 `librviz_widget.so` 是否存在。

README 快速开始、`DEPLOYMENT.md` 和 `qt_frontend/scripts/start.sh` 中缺少 `librviz_widget.so` 时的提示都已改为使用该脚本：

```bash
./qt_frontend/scripts/build_rviz_widget.sh
```

这样部署人员只需要记住一个入口命令，构建路径和 ROS source 逻辑都由脚本处理。
