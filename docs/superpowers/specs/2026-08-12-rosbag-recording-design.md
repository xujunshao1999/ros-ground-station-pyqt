# 地面站 ROS Bag 数据录制设计

## 目标

为 PyQt5 地面站补齐当前只有菜单占位的“录制”功能。用户可以在左侧常驻录制页签中选择地面站本地 ROS Master 当前存在的话题，自定义录制名称和保存目录，设置 ROS Noetic `rosbag record` 的常用参数，并在录制期间持续查看时长、文件大小和运行状态。

本期只实现数据录制，不实现 rosbag 回放、播放时间轴、播放速率、循环播放、`/use_sim_time` 或 `rosbag play --clock`。录制对象是 MQTT-ROS Bridge 已经还原到地面站本地 roscore 的话题，以及同一 roscore 中用户额外选择的其他本地话题；它不等同于机器人端 `rosbag record -a` 获得的全量原始数据。

## 架构

录制能力分为三个边界清晰的组件：

- `RecordingPanel`：左侧录制页签，负责话题选择、名称和参数输入，以及配置、运行、保存、失败等状态展示。
- `RosbagRecorder`：独立录制服务类，接收结构化配置，校验并构造参数数组，通过 Qt `QProcess` 启动、停止和监控 `rosbag record` 子进程。同一时间只允许一个录制任务。
- `MainWindow`：装配面板和录制服务，把录制状态同步到顶部工具栏与底部状态栏，并在应用关闭时协调安全停止。

话题选择模型合并两个来源：`qt_frontend/config/transmit_config.yaml` 提供地面站已配置的机器人传输话题，`rostopic list` 提供当前本地 ROS Master 的真实话题。界面优先展示“已配置、机器人在线且本地存在”的推荐话题，同时允许展开选择其他本地话题。录制命令最终只包含用户勾选且开始录制时仍然存在的话题。

## 技术栈

- Python 3.8，保持 ROS Noetic 兼容
- PyQt5 signal/slot 与 `QProcess`
- ROS Noetic `rosbag record`、`rostopic list`、`rosbag info`
- pytest，Qt 测试使用 `QT_QPA_PLATFORM=offscreen`

## 术语与执行约定

- **地面站本地 ROS Master / roscore**：运行在地面站主机上的 ROS1 Master。Bridge 把从 MQTT 收到的机器人消息重新发布到这里，RViz 和录制进程都订阅这一侧，不直连机器人自身的 ROS Master。
- **Bridge**：`bridge/mqtt_ros_bridge.py`。它把 MQTT 传感器数据恢复为 ROS 消息并发布为 `/{robot_id}/...` 话题；`/tf` 和 `/tf_static` 按项目约定使用公共话题。
- **推荐话题**：同时满足“存在于 `transmit_config.yaml`、对应机器人在线、在本地 ROS Master 当前存在”的话题。它只是界面默认分组和勾选建议，不代表录制服务可以录制尚未发布到本地 roscore 的数据。
- **其他本地话题**：`rostopic list` 返回但未进入推荐分组的话题，包括 Bridge 之外的地面站本地节点话题。用户可以手动勾选。
- **隐藏话题**：话题路径任一段以下划线开头的内部话题。界面的“显示隐藏话题”只控制选择器可见性，不映射为独立的 rosbag 参数；仍然只录制用户显式勾选的话题。
- **bag 文件**：ROS1 rosbag 生成的 `.bag` 文件。压缩作用于 bag 内的数据块，LZ4 和 BZ2 都是无损压缩，不修改 ROS 消息字段、时间戳或序列化内容。
- **分包**：使用 `--split` 按最大文件大小或持续时间把一次录制拆成多个 bag 文件。基础录制名称保持不变，实际文件名由 rosbag 追加分包标识。
- **latched 消息**：ROS1 发布者会向新订阅者立即重发的最后一条消息，例如常见的 `/tf_static` 或地图。分包时使用 `--repeat-latched`，让新分包包含这些消息的当前值。
- **缓存大小**：`rosbag record --buffsize` 的内存缓冲区，单位 MiB。它可吸收短时写入波动，但不能解决 CPU 或磁盘长期吞吐不足。
- **正常停止**：向 rosbag 进程发送 `SIGINT`，等待其写完索引并关闭 bag。直接杀死进程可能留下未索引的文件，因此只在正常停止超时且用户二次确认后强制终止。
- **模拟时间**：ROS 参数 `/use_sim_time` 与 `rosbag play --clock` 配合用于回放，本期录制功能不提供该设置。

## 用户界面

### 左侧录制页签

在现有左侧 `机器人 / 配置 / 事件` 区域新增“录制”页签。默认左栏宽度约 360 px、最小宽度 320 px，用户仍可拖动主分隔条临时放宽。为了适配窄栏，录制页使用单列任务流，不使用包含话题类型、频率和带宽的多列表格。

配置状态从上到下包含：

1. ROS Master 连接状态与刷新按钮。
2. 录制名称，默认 `recording_YYYYMMDD_HHMMSS`。
3. 话题搜索框和可勾选分组树。
4. “推荐话题”分组：公共 `/tf`、`/tf_static` 单独显示，其他话题按机器人 ID 分组。
5. 可折叠的“其他本地 ROS 话题”分组。
6. 可折叠的“保存与录制参数”区域。
7. 已选话题数量、机器人数量和最终文件路径摘要。
8. 固定在底部的“开始录制”按钮。

机器人分组内去掉重复前缀，例如在 `turtlebot_001` 组内显示 `odom`、`scan`；悬停提示展示完整 ROS 话题和消息类型。搜索匹配完整话题名、短名称和机器人 ID。用户关闭“显示隐藏话题”时，已勾选的隐藏话题不得在不可见状态下继续被静默录制；关闭前应取消其勾选或明确提示仍有隐藏选择。

### 名称与保存路径

录制名称与保存目录分开设置。名称允许中文、英文字母、数字、短横线和下划线，去除首尾空白，禁止路径分隔符和仅由点组成的名称。用户不需要输入 `.bag`，应用统一补充后缀并实时预览目标路径。

目标文件已存在时禁止静默覆盖。非分包录制检查 `<名称>.bag` 和 rosbag 录制中的 `<名称>.bag.active`；分包录制检查同一基础名称的现有分包冲突。保存目录必须存在或能够由应用创建，并且当前用户可写。

### 录制中与保存状态

录制成功启动后，左侧可自动切回“机器人”页签。用户再次进入“录制”页时，配置表单替换为只读状态视图，显示：

- 红色录制状态和累计时长；
- 当前 bag 文件或基础名称；
- 当前目录下匹配本次基础名称的文件总大小；
- 录制话题数量；
- 压缩、分包和缓存摘要；
- 警告或 rosbag stderr 摘要；
- “停止并保存”按钮。

录制期间锁定名称、目录、话题和参数，避免界面配置与实际进程不一致。停止后进入“正在保存”状态，所有开始和停止入口临时禁用，直到 rosbag 正常退出并确认 bag 文件不再处于 `.active` 状态。

顶部工具栏在录制期间持续显示红点、时长、当前文件总大小和停止按钮，例如 `● 录制中 00:12:35  1.8 GiB  [停止]`。底部状态栏从“录制: 未启用”改为当前状态摘要；空闲时显示“录制: 就绪”。菜单中的“开始录制”切换到左侧录制页签，“停止录制”调用同一停止流程。

## 话题发现与选择规则

刷新话题时在后台执行 `rostopic list`，不得阻塞 Qt 主线程。发现结果与 `transmit_config.yaml` 及当前在线机器人列表合并：

1. 将 `/tf` 和 `/tf_static` 归入公共变换组，列表中各只出现一次。
2. 对每台在线机器人，将配置话题转换为 Bridge 的本地名称 `/{robot_id}/{topic}`；配置中的 `/tf`、`/tf_static` 保持公共名称。
3. 仅当转换后的话题存在于最新 `rostopic list` 结果时进入推荐组。
4. 剩余本地话题进入“其他本地 ROS 话题”组。
5. 默认勾选所有推荐话题，其他本地话题默认不勾选。
6. 刷新时尽量保留仍然存在的话题的用户勾选状态；已消失话题从可录制集合移除并提示。
7. 点击开始时再次刷新或验证话题存在性。部分话题消失时，列出被移除的话题并允许录制剩余话题；全部消失时阻止开始。

本期不提供“录制全部话题”、正则表达式或按节点录制入口，避免绕过可视化选择造成意外的大流量录制。

## 录制参数

第一版提供以下常用参数：

| 界面参数 | 默认值 | rosbag 参数 | 行为 |
|---|---|---|---|
| 压缩方式 | LZ4 | `--lz4`、`--bz2` 或不传 | LZ4 与 BZ2 均无损；BZ2 标注为 CPU 占用较高 |
| 分包方式 | 不分包 | `--split` | 可选按大小或按持续时间，二者互斥 |
| 分包大小 | 4096 MiB | `--size=4096` | 仅在按大小分包时启用，必须为正整数 |
| 分包时长 | 60 min | `--duration=60m` | 仅在按时长分包时启用，界面支持秒、分、小时并统一构造参数 |
| 缓存大小 | 256 MiB | `--buffsize=256` | 必须为正整数，不提供 `0=无限` 快捷项 |
| 显示隐藏话题 | 关闭 | 无 | 只影响话题选择器 |

分包时自动追加 `--repeat-latched`。第一版不暴露 `--max-splits`，避免录制过程中自动删除最旧分包；也不暴露 `--chunksize`、`--limit`、`--udp`、`--tcpnodelay`、`--node`、`--all` 和 `--regex`。

录制服务使用参数数组启动进程，不拼接 shell 命令字符串。非分包命令等价于：

```text
rosbag record -O /absolute/path/warehouse_patrol_01 --lz4 --buffsize=256 /tf /tf_static /turtlebot_001/odom
```

分包命令等价于：

```text
rosbag record -O /absolute/path/warehouse_patrol_01 --lz4 --buffsize=256 --split --size=4096 --repeat-latched /tf /tf_static /turtlebot_001/odom
```

`-O` 传入不带 `.bag` 的绝对基础路径，由 ROS Noetic rosbag 生成实际后缀和分包文件名。实现阶段必须用聚焦集成测试确认非分包与分包的实际产物，文件预览和冲突检查以该结果为准，不能仅凭字符串假设。

## 录制服务状态机

`RosbagRecorder` 至少包含以下状态：

- `idle`：没有录制进程，可以开始录制。
- `starting`：配置已通过校验，正在等待 rosbag 进程确认启动。
- `recording`：进程存活并已开始写入文件。
- `stopping`：已发送 `SIGINT`，正在等待索引写入和进程退出。
- `completed`：最近一次录制正常结束，随后回到 `idle`，界面保留结果摘要。
- `failed`：启动失败或运行中异常退出，界面展示错误，用户确认后回到 `idle`。

服务通过 Qt 信号发布状态，不允许后台工作直接修改控件。同一时间只允许一个 `QProcess`；`starting`、`recording`、`stopping` 状态下重复开始必须被拒绝。

运行时长使用单调时钟计算。文件大小按本次输出基础名称匹配 `.bag`、分包文件及录制中的 `.active` 文件后求和，定时刷新不得遍历保存目录之外的路径。

## 停止、退出与错误处理

开始录制前阻止以下情况：

- ROS Master 不可用，或者系统找不到 `rosbag` 可执行文件；
- 未选择任何话题；
- 选中话题在开始校验时已全部消失；
- 名称非法、目标冲突、保存目录不能创建或不可写；
- 分包大小、分包时长或缓存大小非法；
- 已有录制任务正在启动、录制或保存。

正常停止时向进程发送 `SIGINT` 并进入 `stopping`。等待时间超过设定上限后，不自动杀进程；界面显示“rosbag 仍在保存”，提供继续等待和二次确认后的“强制终止”。强制终止必须提示 bag 可能需要 `rosbag reindex` 或无法完整读取。

应用关闭时，如有活动录制，先提示“停止并退出”或“取消退出”。选择停止后复用正常停止流程，保存完成后继续关闭；只有停止超时后才提供强制退出选择。`closeEvent` 不得在 Qt 主线程无限等待。

rosbag 异常退出时记录退出码和 stderr 最后若干行，向用户显示可操作的摘要，包括目标目录。磁盘空间不足、权限错误、ROS Master 断开等错误保留原始诊断供日志排查。某个话题在录制途中停止发布不会终止整个录制；状态页可以显示警告，但不能把“暂时没有消息”误判为进程失败。

## 配置持久化

保存目录、压缩方式、分包设置、缓存大小和“显示隐藏话题”作为本机用户偏好持久化，下一次打开录制页时恢复。录制名称每次重新按当前时间生成，不沿用上一次任务名称。话题勾选默认重新基于当前推荐话题生成，避免离线机器人或旧话题被长期隐式保留。

录制输出目录不提交到 Git。若项目提供默认目录，使用项目根目录之外或明确忽略的 `records/`，并确保 `.gitignore` 覆盖 `*.bag`、`*.bag.active` 和该目录。

## 测试与验证

### 无 roscore 单元测试

- 名称、路径、文件冲突和数值参数校验；
- 不压缩、LZ4、BZ2、按大小分包和按时长分包的参数数组；
- 分包自动追加 `--repeat-latched`，且不包含 `--max-splits`；
- 推荐话题与本地话题的合并、公共 TF 去重、隐藏话题过滤和刷新保留选择；
- 状态机合法转换、重复启动拒绝、正常退出和异常退出摘要；
- 使用假进程验证停止发送 `SIGINT`，超时前不强制终止。

### Qt offscreen 测试

- 左侧新增“录制”页签，菜单开始动作可切换到该页；
- 默认名称、文件路径预览、话题搜索和分组勾选；
- 压缩与分包控件联动，非法输入禁用开始按钮并显示原因；
- 配置、启动、录制、保存、完成、失败状态切换；
- 工具栏和状态栏与录制服务状态同步；
- 录制期间配置锁定，两个停止入口调用同一流程；
- 应用关闭时活动录制的确认和异步收尾行为。


### 真实 ROS 集成验证

在 ROS Noetic 环境启动 roscore 和可控测试发布器，实际录制并用 `rosbag info` 检查：

1. 非压缩、LZ4 和 BZ2 文件均可读取，消息数量和时间戳有效；
2. 实际文件名与界面预览一致；
3. bag 只包含用户选择的话题；
4. 按大小和按时长分包生效，每个分包可读取；
5. 分包中的 latched 话题符合 `--repeat-latched` 预期；
6. 点击停止后进程正常退出，不遗留 `.active` 文件；
7. 地面站退出时可以正常停止并保存活动录制。

涉及多机器人 MQTT、Bridge、Docker 和 RViz 时，再启动真实链路验证 bag 能录到地面站实际收到的 `/{robot_id}/...`、`/tf` 和 `/tf_static`。该验证只证明地面站接收侧数据可录制，不代表机器人端未传输话题或 MQTT 传输前的高频原始帧已被保存。

## 本期完成标准

- 当前无处理逻辑的“开始录制/停止录制”菜单变为可用入口；
- 用户可以从推荐话题和其他本地 ROS 话题中手动选择录制集合；
- 用户可以自定义名称、目录、无损压缩、分包和缓存参数；
- 录制服务能够安全启动、监控和停止 ROS Noetic rosbag，并阻止并发录制和静默覆盖；
- 左侧页签、顶部工具栏和底部状态栏一致展示录制状态；
- 聚焦单元测试、Qt offscreen 测试和真实 roscore rosbag 验证通过；
- 回放、模拟时间和机器人端全量录制明确留在后续范围。
