# 命令按钮设置窗口视觉优化设计

## 背景

“命令按钮设置”窗口已经支持四个固定位置、ROS 话题与消息类型选择、消息结构查询、结构化表单和 JSON 双向编辑。功能验证通过后，现有窗口仍较接近 Qt 默认控件的直接排列：左侧位置列表没有配置摘要，右侧基本字段、状态和消息参数缺少清晰分区，底部“清除、取消、保存”三个操作的视觉权重接近，导致用户难以快速扫描配置状态和当前编辑上下文。

本次只优化该对话框的视觉与布局，不改变配置格式、消息结构查询、表单与 JSON 同步、保存语义或命令发送行为。

## 目标

- 将现有双栏结构整理为紧凑的桌面属性编辑器，适合反复扫描和修改四个按钮位置。
- 左侧无需进入编辑区即可区分已配置、未配置和当前选中的位置。
- 右侧明确区分“基本信息”和“消息参数”，减少默认控件堆叠感。
- 查询成功、查询中、缓存、失败和未配置状态具有一致且克制的视觉反馈。
- “保存全部设置”成为唯一主操作，“取消”和“清空当前位置”保持次级层级。
- 沿用应用现有深色操作台主题，在不引入新图标库或外部资源的前提下提升完成度。

## 非目标

- 不改变四槽位配置模型、YAML 文件结构和原子保存逻辑。
- 不改变话题发现、消息类型自动填充、schema 请求和超时机制。
- 不修改结构化表单生成规则、JSON 校验和两种编辑模式的数据同步规则。
- 不美化其他地面站面板，也不重做全局主题。
- 不新增动画、向导步骤、拖拽排序、槽位增删或响应式移动端布局。

## 术语与执行约定

- **槽位（slot）**：命令区固定的四个按钮位置，内部标识仍为 `slot_1` 至 `slot_4`。本设计中的槽位摘要只是显示层，不产生新的配置字段。
- **schema**：机器人 Agent 根据 ROS 消息类型返回的字段树，前端用它生成结构化表单。本设计仅改变 schema 状态的展示方式，不改变协议或缓存策略。
- **结构化表单**：根据 schema 递归生成的 Qt 输入控件。它和 JSON 标签继续编辑同一份消息参数。
- **状态行**：基本信息下方用于显示 schema 查询结果的轻量反馈区域，由状态点和文本组成，不使用大面积提示卡片。
- **主操作**：当前窗口中完成任务的唯一高权重按钮，即“保存全部设置”。清空和取消均为次级操作。
- **运行态配置**：`qt_frontend/config/command_buttons.yaml` 中用户测试时保存的数据。本次视觉实现不得依赖或覆盖其具体内容。

## 已确认的视觉方向

采用紧凑双栏属性编辑器。窗口维持约 `820 × 580` 的现有最小尺寸，左侧槽位导航扩展到约 `190–210 px`，右侧使用剩余空间。整体使用现有 `BG`、`SURFACE`、`SURFACE_2`、`FIELD`、`BORDER`、`TEXT`、`MUTED`、`PRIMARY` 等主题色，不引入新的主色体系、渐变、发光背景或装饰图形。

### 左侧槽位导航

左栏顶部显示小号分组标题“按钮位置”。每个槽位固定两行：第一行是“位置 N”，第二行显示摘要。

- 已配置：摘要优先显示按钮名称；空间允许时附带话题，超长文本在单行中截断并提供 tooltip。
- 未配置：摘要显示“未配置”。
- 当前选中：使用较深的蓝灰背景、可见边框和左侧小状态点，不再依赖整行高亮色块。
- 非选中项保持透明或接近侧栏背景，hover 和键盘 focus 必须可见。

槽位摘要从现有草稿实时计算。修改按钮名称、话题或清空槽位后，左侧对应项立即刷新，但不写入磁盘；仍只有“保存全部设置”执行原子保存。

### 右侧基本信息

右侧顶部增加“基本信息”分区标题，并通过细分隔线延伸到可用宽度。字段名称调整为“按钮名称”“ROS 话题”“消息类型”，输入控件保持现有类型和行为，统一高度、边框和垂直间距。

schema 状态显示在字段下方，采用直径约 `6–8 px` 的状态点和一行文本：

- 查询成功：绿色状态点，“消息结构已在线校验”。
- 正在查询：主题蓝状态点，“正在查询消息结构…”。
- 使用缓存：黄色状态点，“使用缓存消息结构，尚未在线校验”。
- 未验证且无缓存：灰色状态点，“消息结构尚未在线校验”。
- 查询失败或参数错误：红色状态点，显示现有具体错误文本。
- 空槽位：灰色状态点，“当前按钮位置未配置”。

状态行保持固定的最小高度，长错误文本允许换行，避免状态变化引起编辑区明显跳动。

### 消息参数区域

“消息参数”作为第二个分区标题。结构化表单和 JSON 继续使用标签页，但弱化 Qt 默认的独立按钮外观：未选标签使用 muted 文本，选中标签使用亮色文本和底部 `PRIMARY` 指示线。标签页内容区域使用稳定边框和统一内边距，不把整个右侧做成嵌套卡片。

结构化表单控件、递归字段分组和 JSON 编辑器的业务行为不变。JSON 编辑器继续使用等宽字体和滚动条；消息字段很多时只在参数区域内部滚动，基本信息和底部操作保持可见。

### 底部操作区

底部建立独立操作栏，并用顶部分隔线与内容区分开：

- “清空当前位置”放在左侧，使用低权重透明或深色次级样式。
- “取消”和“保存全部设置”放在右侧。
- “保存全部设置”使用 `PRIMARY` 背景和更高字重，是唯一主按钮。
- 保留按钮原有文本、tooltip、快捷键和对话框接受/拒绝行为。

按钮 hover、pressed、disabled 和键盘 focus 都必须清晰，但不得通过缩放改变布局尺寸。

## 组件与实现边界

- `qt_frontend/panels/command_button_dialog.py` 负责布局、对象名或动态属性、槽位摘要刷新和状态行状态映射。
- 对话框专用样式优先通过对象名限定，放在该模块可维护的局部 stylesheet 中，避免改变其他面板；只有确认是全局通用且无回归风险的规则才允许修改 `qt_frontend/theme.py`。
- `qt_frontend/panels/message_form.py` 仅在现有控件无法满足间距和字段层级时做最小视觉调整，不改变数据解析、字段路径或校验行为。
- `qt_frontend/command_button_config.py`、`protocol/`、`agent/`、`bridge/` 和 MQTT 客户端不在本次修改范围内。

## 状态与数据流

打开窗口时，仍从配置存储构建四个草稿并加载第一个槽位。新增的显示逻辑从草稿派生槽位摘要和状态样式，不建立第二份业务状态。用户切换槽位前仍捕获当前草稿，随后刷新旧槽位摘要、加载新槽位字段并更新状态行。

话题或消息类型改变时，沿用现有 schema 请求链路。请求发出后立即显示查询中状态；成功响应、失败响应或超时均通过现有状态字段更新文本与颜色。异步响应仍必须按 robot ID、request ID、slot ID 和消息类型匹配，视觉刷新不得放宽过期响应过滤。

保存、取消和清空继续沿用现有原子存储和草稿语义。视觉刷新不得在切换槽位、状态变化或关闭窗口时产生额外保存。

## 可访问性与稳定性

- 保持现有应用字体，不下载或依赖网络字体。
- 正文和控件文字与背景保持清晰对比，muted 文字仅用于摘要和辅助状态。
- 所有交互继续支持键盘 Tab 导航；当前槽位、输入焦点和按钮 focus 均有可见反馈。
- 控件使用固定或受约束的高度，槽位摘要和长状态文本不得挤压、遮挡相邻控件。
- 窗口在最小尺寸下不出现横向溢出；四个槽位始终完整可见，消息参数区域承担垂直滚动。
- 不使用 emoji 作为新增图标；若使用 Qt 标准图标，必须设置 tooltip 和 accessible name。

## 测试与验证

### 自动化测试

在 `tests/test_command_button_dialog.py` 增加或调整聚焦测试，验证：

- 四个槽位显示名称与配置摘要，空槽位明确显示“未配置”。
- 编辑按钮名称或话题后，槽位摘要更新但配置文件未提前保存。
- schema 查询中、成功、缓存、失败和空槽位映射到正确的状态文本与动态属性。
- 切换槽位、切换结构化表单与 JSON、切换话题后现有草稿和 schema 行为不回归。
- 清空、取消和保存的信号与持久化行为不变。

执行：

```bash
QT_QPA_PLATFORM=offscreen python3 -m pytest tests/test_command_button_dialog.py -v
python3 -m pytest tests/ -v
ruff check qt_frontend/panels/command_button_dialog.py tests/test_command_button_dialog.py
```

### 视觉与运行态验证

从 `master` 启动地面站，在两个 Turtlebot 容器在线时打开设置窗口，至少验证 `820 × 580` 最小尺寸和当前桌面尺寸：

1. 四个槽位摘要、选中态、hover 和键盘 focus 清晰且无文本重叠。
2. `/imu` 和 `/cmd_vel` 的 schema 查询状态正确，结构化表单与 JSON 内容区域不遮挡底部操作。
3. 从 IMU 的 JSON 切换到 `/cmd_vel` 后仍可打开结构化表单。
4. 长按钮名称、长话题、查询超时和长错误信息不会扩大槽位或破坏窗口布局。
5. 保存后模式控制区按钮文字正确刷新，取消不修改磁盘。

Qt offscreen 测试只覆盖控件结构和状态，不等同于真实桌面视觉验证。完成前需要截图检查实际字体、间距、颜色对比、滚动区域和按钮层级。

## 完成判据

- 设置窗口呈现为紧凑双栏属性编辑器，与已确认的 A 方案一致。
- 用户无需点开每个槽位即可判断其名称和是否配置。
- 基本信息、消息参数、状态反馈和底部操作具有清晰稳定的视觉层级。
- 现有 schema 查询、表单与 JSON 同步、四槽位草稿、清空、取消和原子保存行为全部通过回归测试。
- 全量 pytest 和本次修改文件的 `ruff` 检查通过。
- 真实桌面截图在最小尺寸与当前桌面环境下无文本重叠、裁切或不可达控件。
