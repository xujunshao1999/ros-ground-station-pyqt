- `scripts/start.sh` — 一键启动脚本（前置检查 + 自动启动 roscore/mosquitto/bridge）

**目录重命名**
- 将 `qt-frontend/` 改为 `qt_frontend/`，因为 Python 包名不支持连字符

### 1.2 遇到的问题

- **RViz API 变更**：ROS Noetic 中 `rviz::RenderPanel::initialize()` 需要两个参数（SceneManager + DisplayContext），旧版只需要一个，代码需要适配
- **CMake 路径缓存**：目录重命名后 CMakeCache 路径失效，需要清理 build 目录后重新 cmake
- **pip 依赖冲突**：PyQt5 5.15（pip 安装）与系统 Qt 5.12 版本不兼容，卸载 pip 版改用系统 apt 版 `python3-pyqt5 5.14.1`

## 5月7日（周三）— RViz 鼠标修复 + 面板集成 + 联调

### 2.1 RViz 鼠标交互问题（耗时约 4 小时）

**现象**：RViz 3D 视图正常显示网格，但鼠标左键拖动无反应（无法旋转、缩放、平移）。

这是本次开发中最耗时的问题。以下是排查过程的完整记录：

**第一轮：怀疑嵌入方式**
- 尝试了三种嵌入方案：`sip.unwrapinstance` 父窗口、`QWindow.fromWinId` + `createWindowContainer`、C++ 容器 + `sip.wrapinstance`，均无法解决
- 参考 demo 项目 `demo/Ros_Qt5_Gui_App/src/qrviz.cpp`，改用 `rviz::VisualizationFrame` 替代手动创建 RenderPanel，网格正常但鼠标仍不行

**第二轮：怀疑事件传递**
- 在 C++ 中添加了 `QObject::eventFilter` 日志，确认 `QEvent::MouseButtonPress`、`MouseMove`、`MouseRelease` 事件已经到达 `rviz::RenderPanel` 对象
- 说明问题不在 X11/Qt 事件传递层，而在 RViz 内部的事件处理链

**第三轮：怀疑 PyQt5 的 QApplication**
- 写了一个纯 C++ 的最小测试程序，不使用 PyQt5，直接用 C++ 创建 QApplication、QMainWindow，加载同一个 `librviz_widget.so`
- 结果：纯 C++ 测试程序中鼠标完全正常
- 初步结论：PyQt5 的 QApplication 与 Ogre/RViz 的 alien widget 有兼容性问题

**第四轮：发现真因**
- PyQt5 版本测试：先启动程序（有网格、无鼠标），再关掉程序
- 纯 C++ 版本测试：先启动（有网格、有鼠标），再关掉
- 比对两个程序的差异：PyQt5 版调用了 `load_config()`，C++ 版跳过了
- 做对照实验：PyQt5 版跳过 `load_config()` → 鼠标恢复正常；`load_config()` 改为只加载 "Visualization Manager" 部分 → 鼠标仍不行
- **最终结论**：`manager->load()` 会重置 View/Tool 的内部状态，导致 MoveCamera 工具被取消激活

**解决方案**：
- 不调用任何 `load_config` 或 `loadDisplayConfig` 相关函数
- 在 C++ 初始化代码中手动添加 `createDisplay("Grid")` 和 `createDisplay("TF")`
- 保留了 `VisualizationFrame` + `winId()` + `setMouseTracking()` + MoveCamera 工具显式激活的初始化序列

### 2.2 UI 面板集成（耗时约 2 小时）

## 技术要点总结

| 问题 | 根因 | 解决 |
|------|------|------|
| RViz 鼠标失效 | `manager->load()` 重置 View/Tool 配置 | 手动 `createDisplay()`，不调 load_config |
| 目录名含连字符 | Python 包名不能有 `-` | 重命名为 `qt_frontend/` |

## 5月8日计划 — Docker 化 Turtlebot3 测试

### 目标

将 Turtlebot3 仿真放入 Docker 容器中运行，与宿主机上的 Ground Station 分离，模拟真实多机部署场景。

### 架构

```
┌─ Docker: robot-turtlebot-001 ─────┐     宿主机
│  roscore (容器内部)                │     ┌──────────────────┐
│  turtlebot3_gazebo                 │     │ mosquitto (MQTT) │
│  ros1_agent ───────┐              │     │                  │
│   (ros→MQTT 桥接)   │              │     │ mqtt_ros_bridge  │
└─────────────────────┼──────────────┘     │ roscore (宿主机)  │
                      │   MQTT             │ Qt前端 + RViz    │
                      └──────────────────→ └──────────────────┘
```

关键点：两个 roscore 完全隔离，通过 MQTT 通信。

### 需要做的事

**1. 修改 `docker/Dockerfile.ros`**
- 安装 `ros-noetic-turtlebot3-gazebo`
- 安装 `ros-noetic-turtlebot3-slam`（可选，用于 SLAM 建图测试）

**2. 修改 `docker-compose.yml`**
- 新增 `robot-turtlebot-001` 服务定义
- 挂载 X11 socket（`/tmp/.X11-unix`）让 Gazebo 窗口能显示
- 设置 `TURTLEBOT3_MODEL=burger` 环境变量
- Agent 通过环境变量 `$ROBOT_ID` 注入 robot_id，避免多个容器共享同一份 `config.yaml` 时冲突

**3. 修改 `agent/config.yaml`**
- `subscriptions` 保留共用的话题订阅（`/odom`、`/scan`、`/imu`、`/tf`）
- `robot_id` 通过命令行 `--robot-id` 或环境变量注入，不硬编码在文件中

**4. 验证步骤**
1. `docker-compose up -d robot-turtlebot-001` 启动容器
2. `docker-compose logs -f` 确认 agent 连接 MQTT 成功
3. 宿主机启动 `start.sh` 启动 ground station
4. RViz 中添加 Odometry + LaserScan Display
5. 前端命令面板发送速度指令 → Gazebo 机器人移动

### 预期收益

- Turtlebot3 和 Ground Station 完全隔离，互不影响
- 可同时启动多个 Turtlebot3 容器，测试多机器人场景
- 更接近实际部署架构（机器人端 Docker + 地面站宿主机）
